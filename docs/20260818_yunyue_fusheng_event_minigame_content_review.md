## 2. 正式事件构成

| 分类 | 事件 |
|---|---|
| 工作 | “顺便再确认一下”、大家都还没走、会社读空气 |
| 健康 | 复查通知、凌晨仍亮着的屏幕 |
| 生活 | 洗衣房的雨、超市闭店前 |
| 制度 | 住民税通知、医疗补助手续 |
| 家庭 | 家里的视频电话、寄来的包裹 |
| 副业 | 第一次追加修正、资料使用反馈、评论区问题、第一个产品用户 |

- 所有事件为中日双语。
- 所有事件至少包含一个 `realistic` 选项。
- 江湖选项只出现在适合的工作 / MiniGame 场景，不作为固定配额。
- 正式事件为一次性事件；条件未成立的事件不会进入抽选池。
- Major Event 仅在健康 / 制度条件成立时优先，不会无条件抢占普通事件。
- 副业反馈要求对应路线已发生真实行动，不会在未解锁时随机出现。

## 3. 会社读空气 MiniGame

流程：

```text
月度触发事件
  ↓
会议收尾（12秒）
  ↓
明早资料确认（10秒）
  ↓
离场判断（8秒）
  ↓
S / A / B / C / D
  ↓
状态回写并返回本月经营
```

- 每阶段均有普通现实选项。
- Timeout 不是报错，而是记录为该阶段的有效回答并继续。
- 最终评分统一回写 Workplace、Boundary、WorkTrust、Mental、Stress、RecoveryDebt、LossOfControl。
- `stageIndex / answers / stageStartedAt / deadlineAt / result` 持久化；刷新不会重新生成倒计时。
- 旧版只有 Trigger、没有实际 Session 的存档会安全回到月度经营，不进入空白页面。
- 项目炎上和设计书找茬只有不可游玩的接口占位，没有入口和假实现。

## 5. 平衡判定

结论：`事件已形成路线差异，不调整经济数值`。

- 第23月基准清债路线保持成立；各副业路线清债月份没有变化。
- 单路线通常触发1个对应反馈；产品路线触发2个，混合路线中位触发3～4个，事件构成已能反映实际路线。
- IT资料仍是最快清债路线，但 RecoveryDebt 最高；接私活长期 Mental 最低；产品路线继续消耗 Health；内容账号保留较高 Mental 但 Stress 较高。
- 混合路线获得最多副业反馈，同时承担多路线压力，不构成明显无代价最优解。
- 高透支路线仍为 Stress / RecoveryDebt 100，事件没有把透支代价洗白。
- 本轮没有证据要求先修改副业收入；应先观察真实玩家选择分布。

## 8. 下一 Slice 候选（未实装）

以下为用户在本轮人工确认时发现的问题，不在本 Slice 内修改：

1. 工资成长：固定涨薪、担当扩大、带新人后加薪。
2. 饮食支出动态化：不再永久固定42,000 JPY；极端泡面饮食影响身体，收入与生活改善后可上升至约100,000 JPY。
3. 压力消费与吸烟：烟费、压力驱动消费、偶发一天两包及对应 Health / LossOfControl 后果。

这些需求会影响工资、固定支出和生活行为模型，应作为独立 `Income & Living Cost` Slice 先设计触发条件、结算顺序和上限，再使用新的完整执行口令实施。
