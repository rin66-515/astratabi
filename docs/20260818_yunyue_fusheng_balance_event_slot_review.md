## 2. 模拟前提

- 随机行动点及汇率使用正式 `createMonthlyPlan`。
- 行动效果、副业升级、协同效果及收入使用正式副业引擎。
- 固定支出、最低还款、额外还款及利息使用正式 `settleMonth`。
- `reference_no_extra` 不进行自由行动和额外还款，用来确认既存基准路线可在 24 月内清债。
- 其他策略采用相同额外还款规则：每月在可负担范围内依次选择 10,000 / 5,000 / 2,000 RMB。
- 策略会在可执行时持续投入行动点，属于路线压力测试，不等于普通玩家的实际操作分布。
- 第 1 月按正式流程视为序章事件；反复月度计划与月结从第 2 月开始。
- 模拟器为经营数值沙箱；它会持续观察至指定月份，不替代正式游戏的无债月与 Ending 流程。

表内数值均为 500 回固定种子模拟的中位数。完整工具同时返回 P10 / Median / P90。

## 6. 平衡判定

结论：`要観察`，本 Slice 不调整既存数值。

1. **收益最大值偏向 IT资料。** 24 月中位累计收入为 1,455,000 JPY，高于接私活约 30%。但其每月 AP 消耗更高，且 Mental 归零、Stress 饱和，不能仅凭收入判为综合唯一最优。
2. **所有满投入副业策略的 Stress 均趋近 100。** 这说明当前引擎缺少月间压力恢复或压力阈值反馈；直接削弱某一条路线不能解决共同问题。
3. **产品路线具备明确代价。** 它保留初始 Mental，但 Health 降至 30，已形成与现金收益之间的取舍。
4. **内容路线是相对安全路线。** 收益较低，Health / Mental 均保持在初始 65；它并不主动恢复状态。
5. **高透支与接私活结果近似。** 当前正式行动效果没有把持续加班进一步映射到 `recoveryDebt` / `lossOfControl`，所以模拟器无法制造二者的结构性差异。这是后续事件与恢复机制的设计输入，不应在本 Slice 伪造额外惩罚。

建议在普通 Event / Major Event 真正接入、并确定月间恢复规则后复跑同一工具。若 IT资料届时仍在现金、健康、精神、AP 四维上形成支配，再只调整其升级速度或等级收入，不同时改多个参数。

## 7. 月度事件槽位设计

```text
生成新月计划
  ↓
选择并持久化当月事件槽位（同月不重抽）
  ├─ Major Event：优先
  ├─ 普通 Event：按 weight 抽取
  ├─ MiniGame Trigger：进入小游戏待处理状态
  └─ 无可用事件：记录 none
  ↓
自由行动
  ↓
月结
  ↓
既存判定：年度报告 → Final → 无债月 → Stage → 次月
```

- 生产事件注册表当前为空，因此现有可玩流程、节奏与剧情零变化。
- 槽位记录 `elapsedMonth / kind / eventId / status / miniGame`，刷新后不会重抽。
- Major Event 优先于其他可用事件；同级使用既存权重抽取。
- MiniGame Trigger 仅建立通用状态与结果回写接口，不新增小游戏内容或页面。
- Ending Resolver 与月结后的判定顺序未修改。
