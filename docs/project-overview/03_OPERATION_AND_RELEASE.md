# 运维与发布边界

基准日：2026-08-07

## 1. 环境区分

| 环境 | 用途 | 数据 | 对外公开 |
|---|---|---|---|
| 本地开发 | 制造、调试、水印和 ZIP 负载验证 | 模拟管理员、模拟客户、TEST 包 | 否 |
| 本地验收 | 正式包生成前的 Excel/LibreOffice 目视确认 | 脱敏测试数据 | 否 |
| 正式 VPS | 公开站、管理员后台、客户领取和真实文件流 | 正式管理员、客户交付记录、PRODUCTION 包 | 是，仅 HTTPS |
| 外部备份 | 灾害恢复 | 加密备份与摘要 | 否 |

正式环境不直接使用仓库中的本地默认密码、数据库密码、token pepper或交付令牌加密密钥。所有Secret必须在部署时注入。

`PORTAL_DELIVERY_TOKEN_ENCRYPTION_KEY`必须是Base64编码的32字节随机值，并与`PORTAL_ASRAY_ACTIVATION_URL_KEY`分离。当前密文没有密钥版本字段；正式环境不得直接替换该密钥，否则既有管理员详情无法解密。轮换前必须决定旧密钥保留期间或对全部有效链接执行受控重新发放，并记录影响客户、操作者与时间。

## 2. 正式服务器建议

目标规格：Ubuntu 24.04、6 Core、12 GB RAM、100 GB SSD。

该规格可作为云月小铺、交付后台与 ASRAY 模拟项目并行运行的起点，但 100 GB 磁盘比 CPU 更容易成为瓶颈。必须设置：

- 70%：告警并调查增长来源。
- 80%：暂停非必要的本机长期备份和构建缓存增长。
- 85%：禁止新的水印/ZIP 生成任务。
- 90%：重大告警，只允许清理和恢复操作。
- 始终保留至少 10 GB 可用空间。

重点限制 Docker 镜像/构建缓存、容器日志、上传母版、客户 ZIP、临时解压目录和本机备份的增长。

## 3. 网络与权限

- 公网只开放 SSH、HTTP 和 HTTPS；HTTP 仅用于跳转 HTTPS。
- PostgreSQL、Spring Boot 内部端口、管理工具端口不得暴露公网。
- 管理后台使用难猜路径不能代替认证；应采用强密码、会话超时、登录锁定、Secure/HttpOnly/SameSite Cookie、CSRF 和审计。
- SSH 优先使用密钥认证，禁止共享 root 密码。
- 如由客服协助发放，后续增加受限 SUPPORT 权限，不共享主管理员账号。

## 4. 文件存储边界

推荐逻辑目录：

```text
/var/lib/astratabi/packages/
├── masters/       # 不可变母版
├── deliveries/    # 客户专属交付物
├── work/          # 生成中的临时目录
└── quarantine/    # 校验失败或待调查文件
```

- `masters` 只写入新版本，不原地替换。
- `deliveries` 按客户编号、交付编号和版本隔离。
- `work` 不参与长期备份；成功、失败或进程重启后均应清理。
- `quarantine` 不能被客户下载，处理必须有管理员理由与审计。
- 交付文件过期清理后，仍保留数据库记录、manifest、SHA-256 和操作履历。

## 5. 日常操作

### 5.1 本地启动

```powershell
cd <astratabi-portal项目根目录>
docker compose up -d --build
docker compose ps
```

访问 `http://127.0.0.1:18100/`，后端健康检查为 `http://127.0.0.1:18082/actuator/health`。

### 5.2 本地停止

```powershell
docker compose down
```

日常禁止执行 `docker compose down -v`，除非已经明确确认要删除本地数据库和资料包。

### 5.3 正式资料包登记

1. 确认文件名、版本、发布日期和发布阶段。
2. 在隔离环境检查 ZIP 内容，不执行其中任何文件。
3. 核对 SHA-256。
4. 上传母版 ZIP 与 `.sha256`。
5. 确认数据库登记结果、存储路径和审计记录。
6. 通过测试客户生成水印副本并完成目视检查。
7. 只有 PRODUCTION 版本可以进入正式交付。

## 6. 备份与恢复

- 目标 RPO：24 小时。
- 建议 RTO：4 小时。
- 本机备份不是灾害恢复，必须保留 VPS 外部副本。
- 备份文件应加密，密钥与备份分开管理。
- 每月从备份恢复到隔离数据库，校验表数量、关键交付记录和文件摘要。
- 未执行恢复演练的备份只能标记为“已取得”，不能标记为“可恢复确认済”。

## 7. 监控项目

- VPS 磁盘使用率和 inode。
- Docker 容器健康、重启次数和日志增长。
- PostgreSQL 容量、连接数、慢 SQL 和备份结果。
- 水印/ZIP 任务队列长度、耗时、失败数和剩余空间。
- HTTP 5xx、管理员登录失败、下载票据异常和令牌探测。
- TLS 证书有效期。

## 8. 发布与回滚

发布前保存：

- Git 提交号与镜像标签。
- Flyway 版本与 DB 备份摘要。
- 正式母版文件名和 SHA-256。
- 测试成绩书、未解决问题、Release 判定。

回滚原则：应用镜像可回滚；数据库迁移原则上前进修复，不直接删除已应用的 Flyway 迁移。涉及数据结构变化时，必须在详细设计中单独给出回滚或兼容策略。
