## 2. P1：商品目录与发布版本

### 2.1 商品范围

正式商品候选为：

1. 完整项目文档包
2. 基本设计与详细设计范例
3. 需求确认与客户沟通资料
4. 障害、Bug 与 Review 资料
5. 测试式样书与证迹资料
6. PM、发布与运维管理资料
7. 开发岗位专属包
8. 测试岗位专属包
9. 运维岗位专属包
10. PM/PL 岗位专属包
11. 完整模拟项目源码包

`00_開始ガイド` 作为免费展示资料，不单独销售。

### 2.2 主要设计

- 新增 `portal_product`，由稳定的 `product_code` 标识商品。
- 扩展 `portal_package_release`，保存商品、版本、发布标签、发布阶段和发布日期。
- `TEST` 版本只用于模拟和验证，不允许发给正式客户。
- `PRODUCTION` 版本一旦登记不可覆盖；内容变更必须提高版本并产生新的 SHA-256。
- 管理后台的新建交付从有效商品版本中选择，不再手工输入资料包名称。

## 3. P2：水印副本与 ZIP 生成

### 3.1 生成对象

- Excel 文档：每个 Sheet 加入 `ASRAY / {customerCode} / {deliveryNo}` 的可见水印，并写入交付属性；具体兼容方式需以 Microsoft Excel 与 LibreOffice 双端验证结果确定。
- 源码包：不向源文件批量插入注释，改为加入交付许可、manifest 和文件摘要清单。
- `00_開始ガイド`：使用免费样本标识，不包含客户个人信息。

### 3.2 生成控制

- 新增 `portal_delivery_package` 或等价模型，记录母版、交付副本、状态、文件名、摘要、开始/结束时间、失败原因和重试次数。
- 状态按 `QUEUED → RUNNING → SUCCEEDED / FAILED` 管理。
- Worker 并发数初期固定为 1，避免 100 GB VPS 因 ZIP 解压和 Office 文件处理出现峰值。
- 生成过程使用独立工作目录；成功后原子移动至交付目录，失败和重启不得产生可下载的半成品。
- 母版、客户副本和临时工作区严格分离；母版永不原地修改。

### 3.3 交付物

- 客户专属 ZIP
- 对应 `.sha256`
- `DELIVERY_MANIFEST.json`
- 必要时 `DELIVERY_LICENSE.txt` 与 `SHA256SUMS.txt`

## 4. P3：真实下载与重新发放

### 4.1 推荐状态

`DRAFT → PREPARING → READY → ISSUED → EXPIRED / REVOKED`

- `PREPARING`：生成任务执行中。
- `READY`：文件、摘要和检查均完成，但尚未向客户发放。
- `ISSUED`：管理员确认后创建专属链接。
- 包版本改变时新建交付，不覆盖历史交付。

### 4.2 下载规则

- 客户交付链接在指定日期的日本时间 23:59:59 前有效。
- 每次点击下载时创建短期单次票据，并在数据库锁内消费一次下载次数。
- 文件流只能通过有效、未使用且未过期的票据访问。
- 响应禁止公共缓存，下载完成或失败均记录事件。
- 当前代码使用 120 秒票据；设计目标暂定 5 分钟，制造前在详细设计中统一。

### 4.3 重新发放

- 重新发放同一交付时撤销旧令牌并生成新令牌。
- 默认保留已经消费的下载次数；追加次数必须作为另一项管理员操作。
- 新增 `portal_delivery_reissue_history`，保存新旧令牌引用、有效期/次数变更、原因、操作者和时间。
- 原始令牌不写数据库、不写日志、不写审计 JSON。

## 5. P4：Batch 与数据保全

### 5.1 BATCH-001 每日备份

- 每日 03:00 JST 执行 PostgreSQL `pg_dump`，同时生成 SHA-256。
- 对交付、交付文件、重新发放履历、审计和下载事件生成便于调查的压缩导出。
- 数据库全量备份包含管理员表；单独导出用于调查，不代替全量恢复文件。
- 保存策略：日备 14 天、周备 8 周、月备 12 个月。
- VPS 本机只保留最近 2 天，长期副本保存到 VPS 外部。
- 新增 `portal_batch_execution`，记录执行状态、文件、摘要、件数、错误和重试。
- 失败 30 分钟后自动重试 1 次；每月进行一次恢复演练。

### 5.2 BATCH-002 过期清理

- 交付过期 30 天后删除客户专属 ZIP 和工作副本。
- 保留商品母版、数据库交付记录、manifest 摘要和审计履历。
- 清理前检查有效重新发放记录和当前有效链接，避免误删。

## 6. P5：测试与发布

### 6.1 必须完成的测试

- 单体测试：文件名、摘要、ZIP 安全、水印、manifest、状态迁移、次数消费。
- 结合测试：PostgreSQL 锁、事务、Worker 重试、文件存储、Spring Security。
- 综合测试：管理员上传到客户下载的完整流程。
- UAT：人工收款确认、客服发链接、客户领取、重新发放与期限到期。
- 非功能测试：200 MiB 上传、解压上限、并发 1、磁盘不足、进程重启、超时和异常清理。
- 安全测试：CSRF、会话、锁定、路径穿越、ZIP Bomb、令牌泄露、日志脱敏。
- 运维测试：备份、跨机恢复、过期清理、告警和回滚。

### 6.2 发布门槛

- 正式包名称、版本、内容目录和许可条款确定。
- 所有销售文件去除本地路径、密码、密钥、真实客户数据、`.git`、缓存、构建产物和内部草稿。
- Excel 在 Microsoft Excel 与 LibreOffice 中完成全 Sheet 目视确认。
- 生产 Secret 不进入 Git；数据库和后台内部端口不向公网开放。
- HTTPS、日志轮转、磁盘告警、外部备份和恢复手顺准备完成。
- Release 判定、已知问题和回滚条件有书面记录。

## 7. 当前不做

- 在线支付 API、购物车、自动对账。
- 客户注册、客户密码和会员中心。
- 邮件自动营销、多租户和复杂 RBAC。
- Kubernetes、分布式队列或高并发 Worker 集群。

以上能力只有在真实运营量证明必要时再追加，第一版保持人工收款、单管理员审核和受控交付。
