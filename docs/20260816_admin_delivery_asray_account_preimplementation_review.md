## 2. 现状调查

ASRAY账号开通结果已保存在`portal_asray_provisioning.asray_user_id`，客户领取接口也会在资料生成完成后返回账号。然而管理员交付一览使用的`AdminDeliveryResponse`以及详情使用的`AdminDeliveryDetailResponse`均未包含该字段，因此客服只能从客户画面或数据库间接确认账号，无法在交付记录内完成照合。

密码原文不保存于Portal，资料密码仅在生成请求期间使用。Activation URL密文、开通错误详情及内部签名信息也不应进入管理员列表响应。本次只补足已发行User ID和账号状态的只读表示。

## 3. 设计决定

| 区分 | 决定 |
|---|---|
| 一览API | 当前页的交付ID集合一次性查询Provisioning，避免逐行查询 |
| 详情API | 按`delivery_id`取得单条Provisioning，并合并至既有详情响应 |
| 返回字段 | `asrayUserId`、`asrayAccountStatus` |
| 禁止字段 | 资料密码、登录密码、Activation URL密文、错误详情、HMAC Secret |
| 桌面一览 | 增加“ASRAY账号”列；无账号时显示“未发行” |
| 移动一览 | 交付卡片内显示账号或“未发行” |
| 详情 | 只读账号输入框、账号状态、复制账号按钮 |
| 复制失败 | 选中只读账号并提示按`Ctrl+C`，不改写剪贴板以外的状态 |

本次不改变账号生成格式、账号状态迁移、商品权限映射、客户资料密码、ASRAY登录密码及跨系统Provisioning流程。

## 5. 验收条件

1. 已开通交付在管理员一览和详情显示同一ASRAY User ID。
2. 未开通交付显示“未发行”，页面不报错。
3. 详情“复制账号”复制的内容仅为User ID。
4. 管理员响应中不出现密码、Activation密文和内部错误详情。
5. 一览读取Provisioning最多执行一次批量查询，不按行查询。
6. 后端单体测试、全量回归、前端生产构建及本地浏览器启动验证通过；管理员认证后人工目视按当时凭据可用性判定。
